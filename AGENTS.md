# Working on VoiceGen-Service

Read [README.md](README.md), [API.md](API.md) and [BACKENDS.md](BACKENDS.md) before changing behavior. For operating a running service, follow [the service skill](skill/local-voice-studio/SKILL.md). Keep those documents aligned with implementation changes.

## Service boundaries

- The generator serves the studio, Collection, Queue modal, Observability and generation API on localhost:5743. All ready models are usable per request; a startup choice saves the shared admission default, never an exclusive backend.
- The independent queue API on localhost:55205 owns SQLite CRUD, health and `/v1/models`. `ReadyModels` performs read-only setup/runtime checks in each model’s interpreter, without loading weights, downloading assets, importing inference into the queue parent, validating speech payloads or managing workers. Existing entries remain manageable if model storage is absent; new unready submissions return actionable 422.
- `model_registry.json` defines supported IDs/menu order (Higgs, Vox, Qwen, Chatterbox, Index, MOSS, Fish). Setup lists all; serving and both discovery endpoints list only ready models. `service_defaults.json` supplies the initial Higgs default; SQLite `queue_settings.default_model` is the saved default shared by both APIs. Omitted/null model resolves at admission, then is immutable. Idempotent omitted-model replay recovers the original job even after changing the default.
- One project-local `state/queue.sqlite3` holds the global queue and pause switch. Only the generator owns the consumer lease, recovery and execution. Priorities/FIFO, global positions, reordering and Run Now cross model boundaries. Finish a candidate batch before switching. A missing model’s admitted entries stay queued/blocked while eligible work proceeds; recheck readiness without substituting a different model.
- `model_context()` binds metadata/defaults/specs/assets/profile to each request or execution thread. Never mutate a process-global selected profile while APIs run. `runtime_engine.py` manages one backend adapter subprocess using that model’s interpreter. Reuse consecutive same-model children; stop and verify/reap the entire owned group before switching. Native backends retain their per-output low-memory descendants.
- Every backend child keeps the actual global consumer descriptor until OS process exit, including warm idle model memory. GPU/data/consumer reservations also pass per job through private SCM_RIGHTS IPC and into native/LLM descendants. Per-job GPU descriptors close when execution ends. Unverifiable group cleanup is fatal to consumption; never start another backend or treat EPERM as successful exit. Preserve lock safety across parent crashes.
- Health identity is stable: `service:voicegen-service`, `mode:generator`, `api_version:4.0.0`, `queue_scope:shared`, `runtime_model_switching:true`, plus project/database identity. `default_model` and actual `active_model` are separate and never part of daemon identity. Both APIs expose `/v1/models` with ready `data`, modes, default and active fields. Share `ModelList`, `QueueState` and `QueueMove` through inference-free `queue_schemas.py` so their OpenAPI contracts agree; publish global positions and blocked reasons on entries. An unavailable-model retry returns actionable 422 without changing the failed job. No old queue migration, startup-only model routing or compatibility aliases are part of the v4 public contract.
- Queue health uses `service:voicegen-queue`, `role:queue-crud`, `api_version:4.0.0`, `queue_scope:shared`, `project` and `queue_database`. Both VoiceGen health APIs use `api_version`, never ImageGen's `version`; external launcher integrations must verify the actual route payloads as well as isolated fixtures.
- Generator/API/UI access SQLite directly; queue HTTP outage must not stop generation or CRUD. Keep bounded read-only `queue_service` diagnostics separate from SQLite `queue_storage`. Health must remain responsive to database lock contention and must not trigger downloads, restarts or recovery. Return structured 503/Retry-After for SQLite request failures and preserve IDs/keys; never create a fallback database.
- Shared fields stay top-level; model-specific controls use the exact model ID namespace. Flat generator requests use `/api/generate` or `/api/candidates`; the queue’s `/api/queue` accepts an envelope. Speech validation is deferred only for opaque queue payloads; ready routing is required at admission.
- Source navigation reflects set-up models, rather than only the currently selected model. **Design a voice** is enabled when any ready model supports it. Entering a source unsupported by the current model leaves the model selection empty, filters to capable ready models and disables generation/LLM preview until explicitly selected. Preserve the draft. If no design model is ready, keep the tab disabled with hover/focus/tap tooltip: “Switch to a model which supports voice generation: VoxCPM2, Qwen3-TTS, MOSS VoiceGenerator”. Static `supported_models` supplies setup alternatives; `ready_models` and discovery `modes` determine selectable options. Generator API admission rejects unsupported design with actionable 422 before creating jobs; opaque speech validation remains deferred to consumption.

Scheduling uses immutable admission `sequence` plus mutable `queue_order`. Shared SQLite move/run-now methods serialize with claims and reject nonwaiting jobs. Cross-priority moves adopt the anchor priority; Run Now sets immediate and moves first without preemption; automatic switching follows complete batches. Preserve original request fingerprints, even for keyed jobs; PATCH payload/priority immutability remains separate. Keep queue-only scheduling schemas free of inference imports. UI polling must not replace rows during a pointer drag or scheduling request.

## Storage and privacy

`observability.py` owns generator-only resource sampling and `resource_*` tables in the existing queue database; `resource_probe.py` uses bounded, unprivileged ps/ioreg reads with no inference imports. Start sampling only after generator ownership/recovery, before dispatch. Close it after active jobs finish. Preserve queue semantics: telemetry outages drop/report samples and retry, never fail/replay a job. Keep model/session/phase and per-attempt IDs, separate retries, record unavailable counters as null, retain seven days, aggregate long windows with peaks and bounded responses, and avoid joining across session gaps. CPU/RSS cover the generator process tree; GPU counters are device-wide shared-memory figures, never exclusive job use or discrete VRAM. Keep this scope explicit in API/UI/docs. No telemetry collection/UI belongs in the standalone queue process, and no prompts/audio/command lines belong in metric storage. Test with isolated databases and benign fixture charts.

Job monitoring reads existing Higgs/MOSS `logs/native-<job-id>.log` output through `/api/jobs/{id}/logs`. `job_logs.py` bounds reads to 64 KiB, rejects nonregular/symlink files and metadata-supplied paths, and rejects stale/other-attempt output, including retry races. Never expose combined backend/server logs as one job's output. Missing media/logs are a nonfatal empty state; SQLite errors remain 503. The browser renders diagnostic text inertly, keeps logs optional to charts, and labels the separately sampled stage timeline. Do not copy console output, prompts or audio into resource tables.

Keep source, environments, SQLite/journals, process leases and service logs/PIDs inside the serving project. `QUEUE_DB` isolation overrides must stay under project `state/`. Keep model weights, caches, references, saved voices and generated audio on their configured data storage; preserve existing SSD paths and catalogs. Fail clearly on missing model/media volumes rather than creating fallback downloads. The queue API itself must work without the model SSD.

Keep private state, media, weights, environments, local settings and credentials out of Git. Inspect staged files before committing. Do not overwrite or relocate existing data as part of setup or maintenance.

## Commands and checks

Interactive setup lists every model and adds `[SETUP COMPLETE]` only when the model's current assets, volume and compatible runtime pass the existing serving readiness checks. Preserve all numbers, choices and the setup default; completed models can still be selected for a safe rerun. Do not load models, download assets or use a stale marker to build these labels. `make serve` must fail nonzero before model/LLM questions or launching either service if no model passes readiness; explicit MODEL must pass its own checks. An existing environment, partial download or malformed probe response cannot count as successful setup. Cover the real Make entry point with source-only and partial-setup fixtures. Explicit-model and noninteractive setup skip the menu and status scan.

Setup offers `q` to cancel and handles Ctrl+C without a traceback. `setup_lifecycle.py` supervises a newly owned process group for setup-selected and stops its installers/builds on interruption, including stubborn descendants; never signal unrelated processes or change serving shutdown behavior. Preserve downloaded/partial files and all saved data. Announce safe reruns before work: verified model downloads are reused/no-op, while dependencies and support files can be checked/refreshed in place. Retain pinned revisions and propagate real installer failures. Cover cancellation, descendant cleanup, inherited prompt input, and safe reuse with isolated fixtures.

`bootstrap_python.sh` runs dependency-free setup/menu code with an available CPython 3.9+; run mode never downloads. `python_runtime.py` owns per-lock compatibility bounds and reuses compatible target environments before selecting installed bases or setup-only project-local downloads. `bootstrap_uv.sh` pins and verifies the official uv archive; `.python` and `.bootstrap` remain internal and ignored. Honor independent BOOTSTRAP_PYTHON, LLM_PYTHON and QUEUE_BOOTSTRAP_PYTHON overrides, reject incompatible explicit choices, and preserve incompatible/broken environments. Never substitute an interpreter during serving, overwrite a venv, or use the model SSD for interpreter/tool downloads. Validate new supported minors against all pinned dependencies before widening a bound; metadata/wheel resolution is not real inference validation.

- `make queue`: foreground queue API alone; reuse a matching instance.
- `make serve`: choose/save a ready default, ensure/reuse the independent queue API, then run one generator serving every ready model. LLM is enabled by default; `NO_LLM=1` disables it.
- Generator Ctrl-C finishes active work and leaves pending jobs and the queue API intact. `make stop` stops only a verified idle managed generator; `make stop-queue` separately stops the verified queue API.
- Tests live in `tests/`. `make test` discovers `tests/test_*.py` and runs the complete automated suite with fake inference, including queue/generator process isolation and crash/restart recovery. It does not establish real speech quality. `make smoke` performs real inference against a running generator when appropriate to the change and authorized work.

Use isolated project-local test state and benign media fixtures. Preserve pre-existing user-started services and active jobs. After testing or maintenance, finish active test jobs and stop every agent-started generator, queue API and preview; verify listeners are gone. Do not automatically restore Vox or another backend. Do not install login/autostart services or stop unrelated listeners.

Keep the browser brand **Voice Studios** and the shared `ui/icon.svg` consistent across Studio, Collection and Observability. Model selection changes controls and status, never the header brand or app title. The PNG phone icon and ICO favicon are raster versions of that SVG.

Queue actions use decorative local SVG icons with visible text labels and muted neutral surfaces. Keep row actions equally sized and right aligned; preserve icons when pause/resume labels update.
