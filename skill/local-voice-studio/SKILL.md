# Local Voice Studio

## Generate 1–5 voice options on a running server

For multiple options use POST /api/candidates with the normal generation fields, candidate_count (integer 1–5, default 2) and candidate_variation (auto default, distinct, or seed_only). Check health/capabilities first. Auto creates contrasting descriptions for multi-option Vox/Qwen VoiceDesign/MOSS designs: original first, then brighter/darker/focused/open resonance within stated traits. The default startup LLM refines each contrast when candidate_use_llm:true (default) using the active profile in one model load; the service appends a fixed contrast anchor. Without LLM, built-in directions apply. Reference/saved/preset voices, including Higgs, retain conditioning and produce seed-only alternate takes. Explicit distinct for those modes returns422. Seeds increment modulo 2**32; dialogue/accent/emotion/samplers remain unchanged. Listen for actual differences and accent fidelity; none are guaranteed.

Poll GET /api/candidates/{id}; the response contains ordered jobs, resolved candidate_variation, done_count and group status. Distinct jobs/results expose candidate_variant and their actual effective.description while requested.description stays original. Inspect each prompt. All variants freeze atomically before speech; an unplanned LLM group waits after restart with NO_LLM=1, but frozen groups/retries need no LLM. Planning failure errors queued siblings without fallback; retry explicitly. Each completed job.result has its own audio_url/path/id; save the chosen result using POST /api/voices with output_id. UI reuse retains that option's final description, selects seed_only and clears the old shared preview receipt. Existing groups retain historical seed-only behavior.

Groups and all child jobs are committed atomically in the project-local SQLite queue. Use a stable candidate idempotency_key to recover the same group after timeouts/restarts; changed requests with that key fail 409. Candidate and single-take key scopes are separate. Jobs run sequentially with ordinary/immediate queue ordering; one failure does not discard successful options. Monitor partial/error states and explicitly retry only intended failed children through their queue IDs; pending deletion/clear never cancels active work. View all options in History/Queue reopens a group. Existing POST /api/generate remains a single-take API; use /api/candidates for the count selector.

Locate the checkout from the user's location or service.json with the expected name; do not assume an alias or this Mac's paths. Read README.md and API.md. Every backend defaults to http://localhost:5743/; honor an explicit PORT override. Read GET /health and /api/capabilities on the configured port; fetch /openapi.json for the authoritative schema. Preserve model mode, recordings, catalogs and active work.

First terminal setup asks for a storage folder; Enter selects the project, and an external absolute folder creates links and is remembered. AI/scripts should use make setup NONINTERACTIVE=1 or an explicit DATA_DIR to avoid a prompt. Use make setup only if needed; it installs pinned dependencies and verifies pinned model assets. Honor VENV, BOOTSTRAP_PYTHON, DATA_DIR, OUTPUT_DIR and PORT overrides consistently. Confirm external volumes are mounted before creating storage. On this Mac the serving project and venv are under ~/Documents/models/VoiceGen-Service; ignored storage.json keeps DATA_DIR and the shared GPU lock on the SSD. If present, read that file before setup and preserve all linked data directories. A fresh checkout needs no local settings file. storage.json.example is portable; never copy another machine’s local settings blindly. Serving is offline and must not download missing weights implicitly.

Use make serve for the foreground generator (studio UI and generation API on port 5743), or make start for explicitly requested background generator operation. Both ensure an independent queue CRUD service is running on port 55205; it survives generator Ctrl-C. make queue runs CRUD alone in the foreground; make stop-queue separately verifies/stops it. The queue serves no generation UI, performs no inference/model validation and never recovers active jobs. Reuse matching instances; refuse unrelated listeners. make stop verifies an idle managed generator and leaves CRUD running. No automatic login service. Do not stop other model services to free memory without authorization.

The user's default after testing or maintenance is **all agent-started VoiceGen servers stopped**, including the independent queue API. Finish active test jobs, stop verified agent-started generators/CRUD/previews, and verify listeners are gone. Preserve pre-existing user-started services. Do not automatically restore Vox or another backend. Leave agent-started services running only when explicitly requested.

VoxCPM2 supports steps/guidance and emotion with designed or reference voices. Fetch capabilities before choosing controls. A common schema does not mean every backend accepts every setting. Unknown/unsupported settings fail. No speed control or streaming API is exposed. Reference identity/accent/emotion remain approximate; a seed is not a voice lock.

POST /api/generate with text plus description or a saved voice_id/reference_id. Keep passages short and comply with live token/media limits. Optional absolute output_dir refers to this server's filesystem. Include a stable idempotency_key for recoverable retries, poll GET /api/jobs/id, and keep capacity busy until the worker completes even if the client disconnects. No cancellation or progress percentage is promised. On timeout recover the job; do not automatically create duplicates. SQLite jobs resume after restart in original order and reconcile complete WAV/metadata artifacts before synthesis. Legacy JSON jobs without replay inputs stay interrupted errors. Inspect job/History before using a new key.

Return the verified WAV and JSON paths and local playback URL after success. Check actual output rate/duration, cold loading versus synthesis time, and truncation warnings. Do not claim perceptual quality was verified unless audio was actually auditioned. Local links are not phone-accessible; upload/export only when explicitly authorized for that file.

Save reusable recordings using POST /api/voices, with name, catalog description and normalized tags. Search/filter/page through GET /api/voices. PATCH updates metadata without changing audio/original design. Save exact excerpt transcripts where appropriate; long samples save only their first 30 seconds. Uploads retain original bytes plus bounded mono working copies. Never delete user recordings as cleanup.

Run make test for no-GPU validation and make smoke for one small real inference when requested/appropriate. Select Qwen with `MODEL=qwen3` in this same VoiceGen-Service checkout; no sibling Qwen project or source synchronization is required. Stop the active backend using its MODEL/PORT before starting another: all backends share one library and one project-local SQLite queue. Preserve the former Qwen SSD data folders: imported history indexes still resolve their historical audio there. Consolidation backups of private source/configuration and SQLite state are under ignored project-local state/backups. Keep private audio, transcripts, metadata, indexes, jobs, caches and environments outside Git. Do not upload or publish anything without user authorization.

## Combined cloning and performance references

VoxCPM2 accepts `clone_mode: "combined"` with a saved `voice_id` or uploaded `reference_id` and an exact saved/override `ref_text`. This sends the same recording as both `ref_audio` (identity) and `prompt_audio` plus `prompt_text` (recorded performance). Continuation and combined modes reject new emotion/accent directions. A reference description is catalog context, not an applied instruction. The default `clone_mode: "auto"` resolves to combined only for a Vox reference with an exact transcript and blank emotion/accent directions; otherwise it resolves to reference. Explicit modes retain their behavior; existing queued effective modes stay frozen. Check `modes.reference.clone_modes`; Qwen and other unsupported backends reject combined mode. The full text is synthesized in one call, and its transcript counts toward the input budget.

For expressive variants, upload clean recordings of the **same desired speaker**, save each with a distinct performance name, mood tags and its exact spoken transcript, then select the variant for combined cloning. Preview the reference first: tags are organizational notes, not proof of accent quality. The selected recording supplies both identity and performance; a separate identity anchor is not exposed. Private recordings, transcripts and presets remain outside Git. Accent retention and delivery require listening; no accent guarantee is made.

Longer sentence pauses are not automatically aligned or inferred. Preserve raw full-line takes; do not synthesize tiny sentence fragments or treat energy minima as verified sentence boundaries. Reviewed boundary edits can add silence to reach a desired total gap while preserving voiced samples and longer existing gaps. No speed, temperature or accent-strength control is added for VoxCPM2.

## Reviewed pause editing

Completed/history takes offer **Adjust pauses**. Listen, select the entire quiet gap with playback times or fields, add/remove reviewed spans, then create a separate version. Default target is a minimum **total** selected gap of 750ms; longer selected gaps are preserved. The CPU editor only inserts zeros inside explicitly reviewed quiet spans and preserves every source sample and the raw file. Quietness checks do not establish sentence boundaries, and unselected pauses are not automatically adjusted. The API route `/api/artifacts/{id}/pauses` and its exact limits/provenance/retry contract are documented in API.md. Model inference and GPU locks are not involved. Never invent reviewed offsets from energy minima or claim all sentence gaps were verified automatically.

No MODEL selects the configured Higgs TTS 3 default; service_defaults.json is shared with omitted-model queue submissions. Existing Vox storage/runtime paths remain intact. WEIGHTS_DIR reuses existing immutable model files independently of DATA_DIR. Keep source/env/native builds internal and model/cache/private data in configured external storage. Missing linked volumes fail without fallback downloads. A fresh make setup asks once for storage; Enter means project-local. DATA_DIR or NONINTERACTIVE=1 avoids prompts.

Do not run two JobManagers against one DATA_DIR. The lifetime owner lock protects recovery; the shared GPU lock covers all actual load/generation/unload work. Native MOSS/Higgs use one Metal subprocess per job and report model_loaded=false between jobs. Their timing includes cold load; do not compare it as warm synthesis. Preserve native logs for errors. Do not disable memory safeguards or stop unrelated listeners.

Chatterbox Original supports reference cloning/exaggeration/CFG with a fixed1000-token output ceiling, without prompt emotion/accent. Index2.5 supports reference cloning plus separate emotion recording or vector and duration/segment-silence controls, without installed text-to-emotion guidance. Both are experimental on24GB due to observed high MPS driver allocations and slow inference; allocator figures are not physical-RAM peak measurements. MOSS designs from descriptions, cannot clone references, and does not lock identity across lines. Fish/Higgs clone with reference+exact transcript and explicit inline emotion/prosody tags in text. Reject unsupported controls; do not silently rewrite supplied speech or pretend a supported language guarantees a Romanian accent.

Retain exact Bilibili/Fish/Boson research/noncommercial terms and output/attribution conditions as documented. No commercial-use confirmation is required for already authorized personal research use. Copying a venv is not a portable deployment: rebuild from a permanent internal interpreter and the pinned lock. Reuse SSD model paths and rebuild native source at its final internal location so deployment does not depend on an isolated worktree.

Interactive make setup lists all supported models; Enter selects Higgs TTS 3, the configured project default. Interactive make serve gives selection numbers only to models with verified local assets and a compatible installed runtime, using lightweight checks without loading weights. Unavailable models are shown separately without numbers, each with a make setup MODEL=<id> command, and cannot be selected. Enter selects Higgs when ready, otherwise the first ready model clearly marked as the menu default. No ready model lists unavailable models and fails with setup/remount guidance. Explicit MODEL and noninteractive input skip the menu; noninteractive serving preserves the explicit/configured model and fails if it is not ready. No implicit downloads or backend substitution. Use typed chatterbox/indextts option objects for new backend controls; flat aliases are deprecated and cannot be combined with their namespaces. Read model-scoped license notices and authoritative terms in capabilities/UI/startup output, including Higgs's conditional creator grant. Notices do not require acknowledgment.

## Durable queue operation

The generator keeps the existing UI, Collection, Queue modal, prompt previews, candidate batches and generation API on localhost:5743. The separate localhost:55205 queue API exposes only health, OpenAPI and SQLite CRUD; no model registry, worker lifecycle, generation UI or inference imports. QUEUE_PORT overrides its saved port independently of generator PORT. make setup-queue installs minimal pinned HTTP dependencies in .venv-queue without downloading models; existing environments also work via QUEUE_PYTHON. CRUD can run with the model SSD offline.

To enqueue with compute off, POST http://localhost:55205/api/queue with {"model":"voxcpm2","payload":{"text":"Welcome home.","description":"A cultured baritone."},"generate_immediately":false,"idempotency_key":"scene-1"}. model is optional generic metadata, defaulting to higgs independently of the active generator. Responses always return the resolved model; the queue stores any valid identifier without checking a model. The generator validates one Generation payload at consumption, freezes defaults/references/model revision before synthesis, and consumes only its startup model. Others wait. Invalid payloads become inspectable errors without blocking later work. 202 confirms persistence only. Do not put idempotency_key inside payload; use the envelope. For 1–5 candidate batches/LLM diversity use the generator's existing /api/candidates.

CRUD GET /api/queue supports status/model/limit/offset and returns generic rows with payload/model/prepared/status/result/error. PATCH /api/queue/{id} updates waiting priority or an unkeyed/unprepared opaque payload; keyed inputs and consumer-prepared payloads are immutable. DELETE one or clear only removes waiting work. Same key with changed model/payload/priority returns409; replay recovers the original ID even after deletion. Queue keys are separate from generator keys. Retry errors through the generator's explicit retry endpoint or submit a corrected new request. Read API.md and each service's live schema: the same route names on different ports have different bodies.

Both services use the unchanged project-local state/queue.sqlite3. QUEUE_DB is an isolation override restricted to project state/; both processes must agree. API/consumer leases, logs and PIDs are project-local and ignored. CRUD has a separate lease, never claims/resets running entries, and may restart during generation. Only the generator holds the exclusive consumer/recovery lease and shared GPU lock. Generator stop finishes active work and preserves waiting work; CRUD stop leaves generation alone. No heartbeat registry, API-side model selection or login daemon is installed. Legacy SQLite migration is performed by the generator under old/new worker leases before CRUD startup; conflicts fail closed and retain backups.

Use the live schema for `POST /api/queue` (same 202 Job body as `/api/generate`, also `/api/jobs`), GET listing/detail, DELETE one pending entry or clear pending, and POST `/{id}/retry` for an explicitly intended failed-job retry. API generate_immediately defaults false; UI sends true by default. True means next available slot ahead of normal pending work, FIFO among equal priorities, never interrupting current inference. Only the startup backend executes; other pending backends are paused. Do not switch or load models automatically to drain them.

SQLite/journals and the worker owner lock live in ignored serving-project state/; media and legacy JSON remain on configured DATA_DIR storage. Startup migrates the legacy database consistently, retains an SSD backup and fails closed on collisions. Health reports queue_database. The existing shared GPU_LOCK_FILE is held through inference; contention waits without failing admitted jobs. A second data owner must not recover a live queue. Native descendants inherit the actual queue/data-owner and GPU descriptors; an orphaned native child keeps these reservations until it exits. Graceful stop finishes active work and retains pending work. Queue clearing removes pending entries only, retaining tombstones/retry keys and all completed artifacts/History/reference media. It never cancels active inference. Frozen effective settings/transcript plus a reference audio hash prevent silent substitutions after catalog edits; missing/changed bytes fail for review. IndexTTS's separate emotion reference is frozen/hashed too. No duplicate reference snapshot is stored.

A complete matching WAV plus sidecar is reconciled into a done job/index after restart. A crash before the sidecar can repeat synthesis under the original ID, so never promise exactly-once effects. Retry the same request/key after a timeout; errors require explicit retry and deleted keys remain deleted. Keep jobs, outputs and artifact indexes together in storage backups. No new downloads or inference are needed for queue tests; use an isolated SSD validation DATA_DIR and fake engines.

The serving repository is https://github.com/ashwinmahesh/VoiceGen-Service and its source checkout is named VoiceGen-Service. Backend IDs and existing SSD data/catalog paths are independent of that folder name. Preserve them when moving or updating source. Moved virtual environments/native builds require explicit path repair or pinned recreation and validation; do not assume they are relocatable.

Manual Fish tags and Qwen VoiceDesign default to whole-line; explicit incompatible pacing is rejected. Existing queued settings remain frozen and old idempotency hashes compatible. MOSS uses the same controls as approximate total-pause instruction targets in a single native pass; never claim exact timing or separate phrase generation for MOSS. Vox/Higgs remain unchanged. ## Upload recordings directly to Collection

Use multipart POST /api/voices/upload with file and name, optional description/transcript, and repeated tags fields to import a recording and save a Collection voice in one request. HTTP201 returns a Voice; use its id as voice_id and preview its audio_url. Preserve the exact reference transcript or leave it empty if unknown. Limits remain 25 MiB, 1–30 seconds, 8–96 kHz, mono/stereo; original bytes are retained under references/originals and the working voice is normalized to mono16kHz. Uploads do not load/train a model or create a synthesis queue job. The UI action is Collection → Voice library → Upload voice, also available from the studio Saved voice tab. POST /api/references remains a reference import; POST /api/voices saves an already imported reference or generated take. All stored recordings stay private and on the configured data drive. Full-page README screenshots use only synthetic demo data.


## Optional local voice prompt expansion

Check health.prompt_expansion.enabled and capabilities.limits.prompt_expansion first. The LLM is enabled by default in make serve/start; interactive serve asks [Y/n] with Enter on, noninteractive defaults on. NO_LLM=1 (direct Python --no-llm) disables it and skips the question. Retired WITH_LLM/--with-llm controls are unsupported; do not restart a busy service to enable them. Setup adds an isolated Python3.14 .venv-enhancer plus shared pinned Qwen3.5-2B 4-bit assets; existing installations use make setup-llm (LLM_PYTHON override), reusing PROMPT_LLM_DIR or ignored storage.json.prompt_llm_dir. Serving never downloads and fails clearly on missing LLM assets unless explicitly disabled. Weights/private records remain on configured data storage, SQLite remains project-local.

Use POST /api/prompts/expand with generation plus optional written guidance. The LLM sees only description/delivery/accent constraints, never dialogue, reference transcript/audio, IDs or paths. Resolve original clone mode first. Supported: Vox design/flexible reference, Qwen VoiceDesign/CustomVoice, MOSS design, Fish short tags, Higgs one existing catalog control. Unsupported: Vox combined/continuation, Qwen Base, Chatterbox Original, current Index adapter. Fish/Higgs require a written direction and no existing/manual delivery tags. Never silently change a clone mode or translate prose to numeric emotion/CFG controls.

Inspect original and updates; suggestions may repeat guidance or invent a nuance despite valid JSON. Apply deliberately by merging updates into the same request and setting prompt_expansion_id to the returned id. Never alter text/ref_text or claim that expansion guarantees better audio/accent. The UI offers preview/apply/keep original/restore original. Applied guidance remains visible in the form, and a selected take shows its saved expanded prompt independently of current form edits. Reopened History takes retain this view. The UI Prompt expansion switch defaults on when the backend serves the LLM and remembers the choice. Off restores applied guidance, disables previews and sends candidate_use_llm:false for built-in design contrasts. Single-take/reference delivery still requires preview then apply. Startup prints its LLM mode. Original prose is preserved then appended; fields, controls, language and voice context remain validated. Restore receipt.original and omit the ID to undo. Edited context/applied fields require a new preview or removed ID.

Preview creates no speech job, returns409 when busy and422 for unsupported/invalid/failed output. It serializes under the actual shared GPU lease, unloads resident speech weights and uses a short-lived offline LLM child. No retry/fallback/truncation. Queue admission embeds immutable receipt provenance; restart/retry reuses it with plain serving. Distinct design batches can additionally run their one-time per-option planner; choose seed_only to keep the shared preview unchanged. Private receipts under DATA_DIR/prompt-expansions must be backed up with media/state. Consult API.md and docs/voice-prompt-expansion.md for exact bounds, research sources and measured limits. Leave all maintenance/test services stopped.
